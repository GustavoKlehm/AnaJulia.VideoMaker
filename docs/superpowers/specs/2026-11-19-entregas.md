# Entregas de vídeo — spec

Data: 2026-11-19 · Status: implementado, falta aplicar a migration

## Objetivo

A Ana entrega vídeos (stories feitos durante o evento, vídeo final, fotos) direto pelo site: cria a entrega, sobe os arquivos e manda um link para o cliente pelo WhatsApp. É o mesmo fluxo do ExPx (cliente + link), mas para arquivos.

## Decisões

| Tema | Decisão |
|---|---|
| Armazenamento | Supabase Storage, bucket **privado** `entregas`. O cliente assiste e baixa por URLs assinadas (6 h) geradas pela API. |
| Acesso | **Link secreto** `/entrega/<token>` que abre sem login. Quem tem login na área do cliente também vê a entrega em `/cliente`. |
| Cliente | Toda entrega pertence a um cliente de `portal_clients`. Cliente de evento é criado na hora (só o nome, cores padrão da Ana, sem login). |
| Validade | Opcional (sem validade, 7/30/90 dias ou uma data). Vale até o fim do dia, horário de Brasília. Vencida: o link sai do ar; **7 dias depois** o cron apaga os arquivos (dá tempo de prorrogar). |
| Consumo de banda | A lista nunca assina vídeo: só fotos e capas. O vídeo aparece como capa (foto "-still" de mesmo nome, ex.: `IMG_1234.MOV` + `IMG_1234-still.jpeg`) e o `<video preload="none">` só nasce no clique. URL para assistir e para baixar o original é gerada no clique e guardada no navegador (memória + sessionStorage) até faltar 5 min para vencer, para o `src` não mudar e o vídeo não ser baixado de novo. Uploads com `cache-control: max-age=31536000`. |
| Link vazado | "Gerar link novo" troca o token; o antigo para na hora. Também dá para desligar o link sem apagar nada. |

## Modelo de dados

- `portal_deliveries`: client_id, token (24 caracteres, base64url), titulo, descricao, data_evento, expira_em, ativo, arquivos_apagados_em.
- `portal_delivery_files`: delivery_id, path (no bucket), nome original, tipo (mime pela extensão), tamanho.

Arquivos aceitos: mp4, m4v, mov, webm, jpg, png, webp, heic. Limite do bucket 5 GB por arquivo; o limite global do projeto (Storage → Settings) pode ser menor e vale o menor.

RLS: só leitura. Admin vê tudo. Contato logado vê as entregas no ar dos seus clientes (para listar em `/cliente`). Escrita só pela API (service role); o Storage não tem política nenhuma.

## Envio de arquivo

1. `POST /api/portal/entregas/:id/arquivos/envio` `{ nome, tamanho }` → `{ path, signedUrl, token, tipo }`.
2. `PUT signedUrl` com o arquivo no corpo e `content-type: tipo` (o estúdio usa XHR para mostrar o progresso).
3. `POST /api/portal/entregas/:id/arquivos` `{ path, nome }` → a API confere no Storage que o arquivo chegou e registra.

## API

Autenticação igual à da área do cliente: `Bearer <EXPX_SYNC_TOKEN>` ou `Bearer <JWT de admin>`.

| Método | Rota | O quê |
|---|---|---|
| GET | `/api/portal/entregas` | todas as entregas (últimas 300) |
| GET | `/api/portal/clientes/:slug/entregas` | entregas do cliente |
| POST | `/api/portal/clientes/:slug/entregas` | cria `{ titulo, descricao?, dataEvento?, expiraEm?, ativo? }` |
| GET | `/api/portal/entregas/:id` | entrega + arquivos com URLs assinadas |
| PATCH | `/api/portal/entregas/:id` | edita os mesmos campos |
| DELETE | `/api/portal/entregas/:id` | apaga a entrega e os arquivos |
| POST | `/api/portal/entregas/:id/link` | gera link novo |
| POST | `/api/portal/entregas/:id/arquivos/envio` | passo 1 do envio |
| POST | `/api/portal/entregas/:id/arquivos` | passo 3 do envio |
| DELETE | `/api/portal/entregas/:id/arquivos/:fileId` | apaga um arquivo |
| GET | `/api/portal/entregas/:id/arquivos/:fileId/url?modo=assistir\|baixar` | URL assinada de um arquivo, pedida no clique |
| GET | `/api/entregas/:token` | **público**: o que o cliente vê (fotos e capas já assinadas, vídeos sem URL). 404 se não existe/desligado, 410 se venceu |
| GET | `/api/entregas/:token/arquivos/:fileId/url?modo=assistir\|baixar` | **público**: URL de um arquivo, pedida no clique |
| GET | `/api/entregas/limpeza` | cron diário da Vercel (`Bearer <CRON_SECRET>`) |

## Telas

- `/estudio/entregas`: nova entrega (cliente existente ou novo) e lista de todas.
- `/estudio/entregas/:id`: subir arquivos (vários de uma vez, com fila e progresso), ver/baixar/apagar, link com mensagem pronta para o WhatsApp, dados e validade, link novo, apagar.
- `/estudio/clientes/:slug`: seção Entregas com atalho para criar uma já com o cliente escolhido.
- `/entrega/:token`: página pública com as cores do cliente. Assistir, **Baixar**, e no celular **Salvar no celular** (folha de compartilhamento do sistema: galeria, Instagram, WhatsApp). Confere arquivos novos a cada minuto só no dia do evento ou nas primeiras 24 h da entrega (stories chegando); fora disso, botão "Atualizar". Trocar de aba não rebusca nada. O still casado vira capa e não aparece como foto solta.
- `/cliente`: lista as entregas no ar ao lado dos planos.

## Fora do escopo agora

Prévia leve em .mp4 dos vídeos (ideia: gerar no momento do envio, mantendo o original para download), baixar tudo em .zip, envio retomável (TUS) para arquivos muito grandes em conexão ruim, contagem de visualizações/downloads, aviso automático por WhatsApp.
